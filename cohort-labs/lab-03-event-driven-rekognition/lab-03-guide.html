Lab 03 — Event-Driven Image Analysis & Pub/Sub

Services: S3 · Lambda · Amazon Rekognition · Amazon SNS  |  Region: eu-central-1  |  Estimated time: 60 min

Goal

Build an event-driven pipeline that automatically analyzes images using AI the moment they are uploaded to S3. When a .png file lands in your bucket, S3 triggers a Lambda function which calls Rekognition to detect objects and scenes, then publishes a personalized report to an SNS topic — which sends you an email. This pattern is the foundation of async, decoupled, event-driven architectures tested in SAA Domain 3.

Steps

Part A — Create an SNS Topic and Subscribe Your Email

1
Open Amazon SNS → Topics → Create topic.
Type: Standard  |  Name: firstname-lastname-lab3
Leave all other settings at their defaults. Click Create topic.
Copy the Topic ARN shown on the topic details page — you will need it in step 6.
2
In the left navigation click Subscriptions → Create subscription.
Topic ARN: select your firstname-lastname-lab3 topic.
Protocol: Email  |  Endpoint: your email address.
Click Create subscription.
3
Check your inbox for an AWS Notification — Subscription Confirmation email and click Confirm subscription. The subscription status in the console must show Confirmed before continuing.
⚠️ Subscription immediately deactivated? Some email security scanners (Google Workspace, corporate mail filters) automatically follow every link in an email — including the unsubscribe link — which deactivates the subscription before you can act. If this happens:
1. Go to SNS → Subscriptions, select the deleted subscription, click Request confirmation to re-send the email.
2. Open the confirmation email on your phone (where link scanners are less aggressive) and confirm from there.
3. Alternatively, use a personal Gmail or Outlook account that does not pre-scan links.

Part B — Create the Lambda Function

4
Open Lambda in a new browser tab → Create function → Author from scratch.
Function name: firstname-lastname-lab3
Runtime: Python 3.14
Under Permissions, the page notes you can set a custom execution role under Additional settings — scroll down, expand Additional settings, change Execution role to Use an existing role, and select SAA-Lab-Lambda-Rekognition-Role.
Leave all other defaults and click Create function.
5
In the Code tab, replace all the default code with the following. Do not click Deploy yet. 
import boto3
import os
import urllib.parse
from botocore.exceptions import ClientError

rekognition = boto3.client("rekognition", region_name="eu-central-1")
sns = boto3.client("sns", region_name="eu-central-1")

def lambda_handler(event, context):
    record = event["Records"][0]["s3"]
    bucket = record["bucket"]["name"]
    key = urllib.parse.unquote_plus(record["object"]["key"])

    student_name = os.environ.get("STUDENT_NAME", "Student")
    sns_topic_arn = os.environ["SNS_TOPIC_ARN"]

    try:
        response = rekognition.detect_labels(
            Image={"S3Object": {"Bucket": bucket, "Name": key}},
            MaxLabels=10,
            MinConfidence=75,
        )
    except ClientError as e:
        error_code = e.response["Error"]["Code"]
        if error_code == "InvalidImageFormatException":
            sns.publish(
                TopicArn=sns_topic_arn,
                Subject="[Lab 03] Upload Failed — Invalid Image Format",
                Message=(
                    f"Hi {student_name},\n\n"
                    f"Your uploaded file '{key}' could not be analyzed.\n\n"
                    f"Rekognition only supports JPEG and PNG files. "
                    f"Make sure your image is a real .png or .jpg — "
                    f"files renamed from HEIC, WebP, or BMP will not work.\n\n"
                    f"Please convert your image to JPEG or PNG and upload again."
                ),
            )
        raise

    labels = [l["Name"] for l in response["Labels"]]
    numbered = "\n".join(f"{i + 1}. {label}" for i, label in enumerate(labels))

    message = (
        f"Hi {student_name},\n\n"
        f"Rekognition has classified the following things in your uploaded image:\n\n"
        f"{numbered}"
    )

    sns.publish(
        TopicArn=sns_topic_arn,
        Subject="[Lab 03] Image Analysis Complete",
        Message=message,
    )
    return {"statusCode": 200, "labels": labels}
⚠️ Make sure your image is a genuine JPEG or PNG. Rekognition will reject files that merely have a .png extension but are actually HEIC (iPhone photos), WebP, or BMP. Use a screenshot (Windows Snipping Tool / macOS Cmd+Shift+4) or export the image from a photo editor as PNG/JPEG. The updated code above sends you a helpful email if the format is wrong instead of silently failing.
6
Click the Configuration tab → Environment variables → Edit → Add environment variable. Add two variables:
  • Key: SNS_TOPIC_ARN  |  Value: the Topic ARN you copied in step 1
  • Key: STUDENT_NAME  |  Value: your first name (e.g. Alice)
Click Save.
7
Click the Code tab → click Deploy. Wait for the banner confirming the function was updated successfully.

Part C — Create the S3 Bucket and Wire the Event

8
Open S3 in a new browser tab → Create bucket.
Leave Bucket namespace on Account Regional namespace (recommended).
Bucket name prefix: firstname-lastname-lab3 — AWS will automatically append your account ID and region as a suffix. Leave all other defaults and click Create bucket.
9
Open the bucket → Properties tab → scroll to Event notifications → Create event notification.
Event name: get-image-to-rekognition
Leave Prefix empty. Under Suffix, enter .png — this ensures only PNG uploads trigger the pipeline.
Event types: check All object create events. Scroll down to Destination: select Lambda function → Choose from your Lambda functions → select firstname-lastname-lab3.
Click Save changes.

Part D — Test the Pipeline

10
Before uploading, make sure your image is a genuine PNG or JPG. Phone photos (HEIC), WebP screenshots, and renamed files will cause Rekognition to fail.

Convert your image first: go to cloudconvert.com, upload your photo, choose PNG or JPG as the output format, convert and download. Then upload the converted file to S3.
⚠️ Also make sure the SNS_TOPIC_ARN environment variable contains the full ARN — e.g. arn:aws:sns:eu-central-1:123456789012:john-doe-lab3 — not just the topic name. You can verify this in Lambda → Configuration → Environment variables.
11
In your S3 bucket click the Objects tab → Upload → Add files → select your converted .png or .jpg file → click Upload.
12
Wait 10–30 seconds, then check your inbox. You should receive an email that opens with "Hi [your name]," followed by a numbered list of objects Rekognition detected in the image.
13
In Lambda → firstname-lastname-lab3 → Monitor tab → View CloudWatch logs to see the full execution log and confirm statusCode: 200.

Verification

  • Email arrives within 30 seconds of upload, opens with Hi [your name], and contains a numbered list of detected objects
  • CloudWatch log group /aws/lambda/firstname-lastname-lab3 shows a successful invocation with statusCode: 200
  • Uploading a .jpg file does not trigger the pipeline (suffix filter working)

Key Exam Concepts

  • Event-driven decoupling: S3, Lambda, and SNS are all independent services; replacing any one of them does not require changing the others
  • S3 Event Notifications: Can target Lambda, SQS, or SNS — suffix/prefix filters prevent processing unintended objects
  • Amazon Rekognition: Fully managed ML vision service — no model training needed; key for image/video analysis questions
  • SNS Fan-out: A single SNS Publish can trigger multiple subscribers (email + SQS + Lambda) simultaneously
  • Lambda environment variables: Use env vars for configuration values (ARNs, feature flags) — never hardcode sensitive values in code
  • Asynchronous invocation: S3-triggered Lambda is asynchronous — Lambda retries on failure; events can be sent to a Dead Letter Queue
